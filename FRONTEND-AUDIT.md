# CampusStay frontend audit

## Before implementation

The nested Campus-Stay checkout contains active frontend, authorization and migration changes. This review covers the HTML, CSS and browser JavaScript in that checkout. The existing profile reader already normalizes unapproved owners to students and supplies the application status. Route guards, public inventory queries, private media signing and revisioned owner drafts are reusable.

* **Navigation.** The homepage hard-codes both dashboard cards and footer links. Shared navigation renders a local cache first, omits application state, labels owner listings “Wishlist” and restores only the sign-in control on logout. Several account pages lack mobile or theme controls.
* **Header geometry.** The base navbar centers a fixed box using left 50% and translateX. Dashboard auth-ready applies a persistent fadeUp transform to every body child, including the navbar. At 375 px the dashboard header extended from x=183 to x=535. At 1024 px it extended to x=1470. The final experience stylesheet also clips dropdowns with overflow hidden.
* **Glass and buttons.** Premium draws a navbar pseudo-element. The glass engine adds refraction and reflection layers while experience.css adds a separate displacement layer and bright specular inset. The GSAP button initializer explicitly inserts four colored blobs, a reflection and ripples.
* **Gallery.** A single image still inherits a two-column gallery. Inline heights and column templates defeat mobile rules. Thumbnails use raw image elements with click handlers and no error handling. An empty gallery builder can substitute an unrelated stock photo. The signed URL resolver exists. The precise cause of any particular live failed URL requires authorized records.
* **Inventory.** Public discovery already requires published, verified, available KIT inventory within 5 km. Detail lookup accepts any authorized property ID and labels some distances as KIT without establishing eligibility. Early college seed data references Pune. The current frontend has no Deccan Gymkhana listing fixture. The production origin of the reported record is unconfirmed.
* **Property cards.** Several layers specify media heights, tilt and grid widths. The shared card displays an unrated chip and omits city. Video rows can become primary images. Owner property cards use stock fallback photos.
* **Owner flows.** A seven-step draft wizard, facilities lookup, camera, image optimization and revision-based uploads already exist. Device coordinates are accepted without owner confirmation or a derived campus distance. The existing Google map is a display-only iframe. Dashboard error paths can leave placeholder counts indefinitely.
* **Type, theme and spacing.** Styles, luxe and experience redefine fonts and tokens. Luxe applies Quincy to both body and display, including controls. Fixed hero minimum heights and generic section padding also apply inside compact dashboards and search results. Account pages load different style combinations. The public category explorer can use stock photography independently of published inventory.
* **Authorization boundary.** Frontend navigation should reflect getAuthContext and the normalized profile. Authorization remains with the route guard and backend policies. The inspected route guard redirects a student requesting an owner route to the application.
